# Add the `agent_controller_open_tasks` gauge vector and its accessor

<summary>

- The controller now declares a Prometheus gauge family named `agent_controller_open_tasks`, labelled by `vault`, `phase` and `task_type`.
- The family is a gauge, not a counter, because it reports a level: the current number of open records in each pair, not a running total.
- The declared label order is `vault`, `phase`, `task_type`, and that order is the argument order every caller must use.
- Business code reaches the family through one new method on the existing metrics interface, so tests can substitute a fake.
- The generated metrics fake is regenerated so the whole module still compiles.
- The family's documentation states that the value is a level and that a pair which empties disappears from the exposition rather than lingering at zero.
- A new package spec proves the family is registered, is a gauge, and carries exactly those three label names.
- Nothing is pre-registered at start-up: the pair set depends on data, so a fresh pod publishes no census series until its first successful pass.
- No configuration knob, no new file in `main.go`, and no change to any existing series.

</summary>

1. **Declare the gauge vector in `pkg/metrics/metrics.go`.** Add it immediately after the existing `TaskAgeBucketTasks` variable and before `func init()`, so the series are grouped together. Use exactly this shape and this doc comment verbatim. Do not add lines above the `level` paragraph — the AC 3 probe in requirement 2 only reaches 20 lines above the `Name:` line, so an extra paragraph above `level` pushes it out of the window and the grep silently returns 0:

   ```go
   // OpenTasks is the number of open task records in each (phase, task_type) pair
   // of this controller's own vault.
   //
   // It is a level, not a counter: the dedicated metrics ticker recomputes it from
   // scratch on every pass and Set()s each pair's count, so the value is the
   // board's count rather than a running total, and two passes over an unchanged
   // board publish the same value.
   //
   // A pair that empties disappears from the exposition entirely rather than
   // lingering at 0: the recompute deletes the series for every pair the previous
   // pass published and this pass did not see, scoped to this controller's own
   // vault label so another controller's series are never touched.
   //
   // There is no init() pre-initialisation. The pair set is data-dependent, so no
   // fixed series can be seeded at registration; a fresh pod publishes no census
   // series until its first successful pass.
   var OpenTasks = promauto.NewGaugeVec(
       prometheus.GaugeOpts{
           Name: "agent_controller_open_tasks",
           Help: "Number of open task records per (phase, task_type) pair, by vault. A pair that empties disappears from the exposition rather than lingering at 0.",
       },
       []string{"vault", "phase", "task_type"},
   )
   ```
