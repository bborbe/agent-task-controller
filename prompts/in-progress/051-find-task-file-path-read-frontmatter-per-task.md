# Read each listed task's frontmatter in the FindTaskFilePath walk

<summary>
- A result whose task identifier is missing from the lookup index finds its task file again
- A task is no longer dropped just because the vault listing does not carry its frontmatter
- The regression spec drives the real walk through the listing projection the vault API actually returns
- Matching through a task's previous identifier still works
- A listed task that has since disappeared is skipped rather than treated as an error
- A duplicate identifier still fails loudly, naming both files
</summary>

<objective>
Make the fallback walk in `FindTaskFilePath` able to match a task again. It currently matches on frontmatter that the vault listing never returns, so any result whose identifier misses the lookup index is dropped after three attempts and its Kafka offset advances. Only an index hit lands a result today.
</objective>
